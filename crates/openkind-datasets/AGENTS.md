# AGENTS.md — openkind-datasets

> Pinned, verified local evaluation-dataset installations for OpenKind
> benchmarking. Read this before changing dataset acquisition.

## Crate Purpose & Boundaries

`openkind-datasets` downloads labeled public datasets from the Hugging Face
Hub at exact pinned revisions into a per-user cache outside the repository,
verifies every file digest, and reads installed parquet shards back as JSON
rows. It exists so `openkind-bench dataset eval` can produce model-quality
evidence; no other crate consumes it.

Boundaries:

- Downloads happen **only** under the explicit `openkind-bench dataset pull`
  and `dataset pin` commands. Construction, local reads, builds, and tests
  never touch the network. This extends workspace invariant 6 to datasets:
  dataset bytes are never committed to this repository and never
  redistributed — the checked-in registry pins identities, revisions,
  sizes, and digests only.
- There is no public mirror for datasets (mirroring would be
  redistribution). The registry is checked into this crate and compiled in
  via `include_str!`.
- Methodology, commands, and interpretation rules are owned by
  [`docs/BENCHMARKS.md`](../../docs/BENCHMARKS.md#dataset-accuracy-evaluation);
  environment variables by [`docs/ENV.md`](../../docs/ENV.md#benchmark-dataset-variables).
  Do not duplicate them here.

### Critical Invariants

1. **Leaf crate**: depends only on external crates (reqwest, tokio, arrow,
   parquet, fs2, sha2). No openkind crate depends upward from here, and
   nothing depends on `openkind-model-store` from here; the verified
   downloader is an adapted sibling of the model-store one, not a shared
   module.
2. **Pinning**: every entry pins the 40-hex `main`-branch commit, the
   40-hex `refs/convert/parquet` commit, and per-file size + SHA-256. All
   three are enforced at validation and verification time.
3. **Auth hygiene**: token resolution is `HF_TOKEN` → `HF_TOKEN_PATH` → the
   `hf auth login` token file (under `HF_HOME`) → anonymous. The token
   value is never logged or serialized; only its source is reported.
4. **Registry/definition sync**: `DATASET_DEFINITIONS` (the compiled-in
   allowlist) and the registry entries must agree — the in-module test
   `registry_entries_and_definitions_stay_in_sync` enforces it, mirroring
   the model-store catalog test.
5. **License discipline**: curated entries carry license and gating
   metadata. The core set is fully open; gated or non-commercial datasets
   are excluded until a deliberate decision adds them, and their bytes stay
   download-only regardless.

## Key Files & Types

- [`src/lib.rs`](./src/lib.rs): crate docs, `Error`/`Result`, embedded
  `DATASETS_JSON`.
- [`src/registry.rs`](./src/registry.rs): `DatasetRegistry`, `DatasetEntry`,
  `DatasetFile`, `Gated`, `TemplateRef`; validation (paths stay inside
  declared configs and used splits; sizes sum under a 2 GiB cap).
- [`src/definitions.rs`](./src/definitions.rs): `DATASET_DEFINITIONS`, the
  curated allowlist `dataset pin` can resolve (name, repo, splits, configs,
  license, gating, template provenance at the reviewed Bonn commit).
- [`src/auth.rs`](./src/auth.rs): Hugging Face token resolution with
  explicit-source errors instead of silent anonymous degradation.
- [`src/store.rs`](./src/store.rs): `DatasetStore` — `pull`, `pin`, `rm`,
  `verify`, `installed`, `list`; resumable digest-verified downloads with
  strict `Content-Range` validation, symlink-safe `.part` files (via
  `O_NOFOLLOW` on Unix; a `symlink_metadata` pre-check plus post-open size
  check elsewhere), content-addressed blobs, fs2 locks, staged installs (the
  model-store discipline adapted to
  `huggingface.co/datasets/.../resolve/<sha>/<path>`), and stage cleanup
  removing abandoned `.stage-*` directories without following symlink targets.
- [`src/rows.rs`](./src/rows.rs): parquet → JSON rows for the installed
  column types; unsupported types fail with the type name.
- [`registry/v1/datasets.json`](./registry/v1/datasets.json): the committed
  pinned registry (generated by `dataset pin` output; edit by re-pinning,
  not by hand).
- Install layout under the cache root: `datasets/<name>/files/<shard>`,
  `datasets/<name>/entry.json`, `blobs/sha256/<digest>`, `locks/`.

## Critical Gotchas & Rules

1. **The convert branch moves.** `refs/convert/parquet` is re-generated
   when upstream data changes; that is why both revisions are pinned and
   per-file digests verified — the bytes, not the ref, are the truth.
2. **`dataset pin` installs as a side effect** and refuses when the dataset
   is already installed (`dataset rm` first). The printed entry is what
   belongs in the registry; committing it is a human review step.
3. **Tree listing caps**: metadata fetches are bounded at 64 MiB; installs
   are capped at 2 GiB per dataset.
4. **Gated repos**: a 401/403 becomes an actionable error naming
   `hf auth login` and the terms click-through, never a silent retry.
5. **banking77's option set** is derived from the eval split's `label_text`
   values (sorted, deduplicated) — both splits must be offered the same
   option set; do not "fix" this to be split-local.
6. **Reusable Blob Verification & Stage Cleanup**:
   Existing blobs must be verified before reuse; digest mismatches unlink the
   corrupted blob so it can be cleanly refetched. Store operations clean up
   leftover `.stage-*` directories under the global lock while preserving
   installed snapshots and resumable partial downloads. Empty store roots are
   rejected before I/O.

## Verification Commands

```bash
cargo check -p openkind-datasets
cargo test -p openkind-datasets
```

Operator-only (networked, never in CI):

```bash
cargo run -p openkind-bench -- dataset list
cargo run -p openkind-bench -- dataset pull <name>
cargo run -p openkind-bench -- dataset verify <name>
cargo run -p openkind-bench -- dataset pin <name>
```
