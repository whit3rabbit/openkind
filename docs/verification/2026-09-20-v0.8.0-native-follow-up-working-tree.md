```bash

  --example qwen35_model_stress -- <pinned-checkpoint-root> <K>
```

no candidate-state fan-out, and reported an unchanged root. Results:

semantic high-K quality. The harness did not emit full probability/argmax/policy
parity for these cells.

## 3.11 native service smoke

The daemon was launched on loopback with the native alias, pinned offline
bundle/checkpoint/tokenizer paths, concurrency 1, queue 1, and gRPC disabled.

- `/health` returned HTTP 200.
- `/v1/models` advertised the native alias and `qwen35-native-cpu` backend.
- A real `/v1/systemone` request with explicit Choice `__none__` returned HTTP
  200 and typed Noul, Choice, and Score answers.
- With concurrency 1 and queue 1, two concurrent native requests returned HTTP
  200 and a third returned HTTP 529 in `0.000656` seconds.
- A client cancelled after one second while native work was running; the next
  request returned HTTP 200 after the blocking work released its permits.
- A queued client cancellation was followed by a later request that returned
  HTTP 200, confirming queue recovery after cancellation propagation.
- Twenty consecutive health probes passed. The daemon remained at 1,488,720 KB
  RSS, 16 threads, and 14 open-descriptor lines before and after the probe
  loop.
- SIGINT produced a clean daemon exit.

This is lifecycle smoke evidence. It is not queue-inclusive production
throughput, long-duration soak, telemetry, or deployment-promotion evidence.
